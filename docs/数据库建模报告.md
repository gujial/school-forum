# 校园论坛平台数据库建模报告

## 1. 概述

### 1.1 报告目的
本报告详细描述了"可圈可点"校园论坛平台的数据库建模过程，包括概念数据模型(CDM)和物理数据模型(PDM)的设计。

### 1.2 建模工具
- **概念建模**: DOT语言 + Graphviz
- **物理建模**: DOT语言 + Graphviz
- **数据库**: OceanBase (MySQL兼容)
- **建模方法**: 实体关系模型(ER Model)

### 1.3 建模原则
- 遵循第三范式(3NF)设计原则
- 确保数据完整性和一致性
- 优化查询性能
- 支持系统扩展性

## 2. 概念数据模型(CDM)

![CDM](./images/CDM概念数据模型.svg)

### 2.1 模型概述
概念数据模型从业务角度描述了系统中的主要实体、属性和关系，不涉及具体的技术实现细节。

### 2.2 主要实体

#### 2.2.1 用户管理域
- **用户(User)**: 系统的核心实体，代表注册用户
- **头像(Avatar)**: 用户头像信息
- **管理员(Admin)**: 具有特殊权限的用户
- **关注关系(Follow)**: 用户间的关注关系

#### 2.2.2 内容管理域
- **推文(Tweet)**: 用户发布的主要内容
- **评论(Comment)**: 对推文的评论和回复
- **媒体(Media)**: 图片、视频等媒体文件
- **标签(Tag)**: 内容分类标签
- **推文标签关联(TweetTag)**: 推文与标签的多对多关系

#### 2.2.3 社交互动域
- **点赞(Like)**: 用户对推文的点赞记录
- **私信(Message)**: 用户间的私信消息
- **举报(Report)**: 内容举报记录

### 2.3 实体关系

#### 2.3.1 用户相关关系
- **用户-头像**: 1:1关系，一个用户拥有一个头像
- **用户-管理员**: 1:0..1关系，用户可能成为管理员
- **用户-推文**: 1:N关系，一个用户可以发布多条推文
- **用户-评论**: 1:N关系，一个用户可以发表多条评论
- **用户-点赞**: 1:N关系，一个用户可以点赞多条推文
- **用户-消息**: 1:N关系，一个用户可以发送/接收多条消息
- **用户-举报**: 1:N关系，一个用户可以举报多条内容

#### 2.3.2 内容相关关系
- **推文-评论**: 1:N关系，一条推文可以有多个评论
- **推文-媒体**: 1:N关系，一条推文可以包含多个媒体文件
- **推文-标签**: M:N关系，通过TweetTags关联表实现
- **推文-点赞**: 1:N关系，一条推文可以获得多个点赞
- **推文-举报**: 1:N关系，一条推文可能被多次举报

#### 2.3.3 社交关系
- **用户-关注**: M:N关系，通过Follows表实现
- **评论-父评论**: 1:0..1关系，支持评论嵌套结构
- **推文-父推文**: 1:0..1关系，支持推文转发

### 2.4 实体属性

#### 2.4.1 用户属性
- **用户ID**: 唯一标识符
- **用户名**: 用户登录名，唯一
- **邮箱**: 用户邮箱地址，唯一
- **密码**: 加密后的密码哈希值
- **背景图**: 个人资料背景图片URL
- **创建时间**: 账户创建时间

#### 2.4.2 推文属性
- **推文ID**: 唯一标识符
- **用户ID**: 发布者ID，外键
- **父推文ID**: 父推文ID，支持转发
- **内容**: 推文文字内容
- **创建时间**: 发布时间

#### 2.4.3 评论属性
- **评论ID**: 唯一标识符
- **推文ID**: 所属推文ID，外键
- **用户ID**: 评论者ID，外键
- **父评论ID**: 父评论ID，支持嵌套
- **内容**: 评论内容
- **创建时间**: 评论时间

#### 2.4.4 媒体属性
- **媒体ID**: 唯一标识符
- **推文ID**: 关联推文ID，外键
- **媒体URL**: 文件存储路径
- **媒体类型**: 文件类型(image/video/all)

#### 2.4.5 标签属性
- **标签ID**: 唯一标识符
- **标签名称**: 标签名称，唯一

#### 2.4.6 关注属性
- **关注者ID**: 关注者用户ID，外键
- **被关注者ID**: 被关注者用户ID，外键

#### 2.4.7 点赞属性
- **点赞ID**: 唯一标识符
- **用户ID**: 点赞者ID，外键
- **推文ID**: 被点赞推文ID，外键
- **创建时间**: 点赞时间

#### 2.4.8 消息属性
- **消息ID**: 唯一标识符
- **发送者ID**: 发送者ID，外键
- **接收者ID**: 接收者ID，外键
- **推文ID**: 关联推文ID，外键
- **评论ID**: 关联评论ID，外键
- **内容**: 消息内容
- **创建时间**: 发送时间

#### 2.4.9 举报属性
- **举报ID**: 唯一标识符
- **推文ID**: 被举报推文ID，外键
- **评论ID**: 被举报评论ID，外键
- **举报内容**: 举报原因描述
- **创建时间**: 举报时间

## 3. 物理数据模型(PDM)

![PDM](./images/PDM物理数据模型.svg)

### 3.1 模型概述
物理数据模型基于概念数据模型，添加了具体的技术实现细节，包括数据类型、约束、索引等。

### 3.2 数据库表结构

#### 3.2.1 用户管理表

**Users表**
```sql
CREATE TABLE Users (
    user_id BIGINT PRIMARY KEY AUTO_INCREMENT,
    username VARCHAR(50) NOT NULL UNIQUE,
    email VARCHAR(100) NOT NULL UNIQUE,
    password VARCHAR(255) NOT NULL,
    bg_url TEXT,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

**Avatar表**
```sql
CREATE TABLE Avatar (
    user_id BIGINT PRIMARY KEY,
    avatar_url TEXT,
    FOREIGN KEY (user_id) REFERENCES Users(user_id)
);
```

**Admins表**
```sql
CREATE TABLE Admins (
    user_id BIGINT NOT NULL,
    FOREIGN KEY (user_id) REFERENCES Users(user_id)
);
```

**Follows表**
```sql
CREATE TABLE Follows (
    follower_id BIGINT NOT NULL,
    following_id BIGINT NOT NULL,
    PRIMARY KEY (follower_id, following_id),
    FOREIGN KEY (follower_id) REFERENCES Users(user_id),
    FOREIGN KEY (following_id) REFERENCES Users(user_id)
);
```

#### 3.2.2 内容管理表

**Tweets表**
```sql
CREATE TABLE Tweets (
    tweet_id BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id BIGINT NOT NULL,
    parent_id BIGINT,
    content TEXT,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (user_id) REFERENCES Users(user_id)
);
```

**Comments表**
```sql
CREATE TABLE Comments (
    comment_id BIGINT PRIMARY KEY AUTO_INCREMENT,
    tweet_id BIGINT NOT NULL,
    user_id BIGINT NOT NULL,
    parent_id BIGINT,
    content TEXT NOT NULL,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (tweet_id) REFERENCES Tweets(tweet_id),
    FOREIGN KEY (user_id) REFERENCES Users(user_id)
);
```

**Media表**
```sql
CREATE TABLE Media (
    media_id BIGINT PRIMARY KEY AUTO_INCREMENT,
    tweet_id BIGINT,
    media_url TEXT NOT NULL,
    media_type VARCHAR(10) NOT NULL,
    FOREIGN KEY (tweet_id) REFERENCES Tweets(tweet_id)
);
```

**TAGS表**
```sql
CREATE TABLE TAGS (
    tag_id BIGINT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(50) NOT NULL UNIQUE
);
```

**TweetTags表**
```sql
CREATE TABLE TweetTags (
    tweet_id BIGINT NOT NULL,
    tag_id BIGINT NOT NULL,
    PRIMARY KEY (tweet_id, tag_id),
    FOREIGN KEY (tweet_id) REFERENCES Tweets(tweet_id),
    FOREIGN KEY (tag_id) REFERENCES TAGS(tag_id)
);
```

#### 3.2.3 社交互动表

**Likes表**
```sql
CREATE TABLE Likes (
    like_id BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id BIGINT NOT NULL,
    tweet_id BIGINT NOT NULL,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (user_id) REFERENCES Users(user_id),
    FOREIGN KEY (tweet_id) REFERENCES Tweets(tweet_id),
    UNIQUE KEY unique_user_tweet (user_id, tweet_id)
);
```

**Messages表**
```sql
CREATE TABLE Messages (
    message_id BIGINT PRIMARY KEY AUTO_INCREMENT,
    sender_id BIGINT NOT NULL,
    receiver_id BIGINT NOT NULL,
    tweet_id BIGINT,
    comment_id BIGINT,
    content TEXT NOT NULL,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (sender_id) REFERENCES Users(user_id),
    FOREIGN KEY (receiver_id) REFERENCES Users(user_id),
    FOREIGN KEY (tweet_id) REFERENCES Tweets(tweet_id),
    FOREIGN KEY (comment_id) REFERENCES Comments(comment_id)
);
```

**Reports表**
```sql
CREATE TABLE Reports (
    report_id BIGINT PRIMARY KEY AUTO_INCREMENT,
    tweet_id BIGINT,
    comment_id BIGINT,
    report_content TEXT,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

### 3.3 索引设计

#### 3.3.1 主键索引
- 所有表的主键字段自动创建主键索引

#### 3.3.2 唯一索引
- Users.username (UNIQUE)
- Users.email (UNIQUE)
- TAGS.name (UNIQUE)
- Likes(user_id, tweet_id) (UNIQUE)
- Follows(follower_id, following_id) (UNIQUE)
- TweetTags(tweet_id, tag_id) (UNIQUE)

#### 3.3.3 外键索引
- Tweets.user_id → Users.user_id
- Tweets.parent_id → Tweets.tweet_id
- Comments.tweet_id → Tweets.tweet_id
- Comments.user_id → Users.user_id
- Comments.parent_id → Comments.comment_id
- Media.tweet_id → Tweets.tweet_id
- Likes.user_id → Users.user_id
- Likes.tweet_id → Tweets.tweet_id
- Messages.sender_id → Users.user_id
- Messages.receiver_id → Users.user_id
- Messages.tweet_id → Tweets.tweet_id
- Messages.comment_id → Comments.comment_id
- Reports.tweet_id → Tweets.tweet_id
- Reports.comment_id → Comments.comment_id
- Avatar.user_id → Users.user_id
- Admins.user_id → Users.user_id
- Follows.follower_id → Users.user_id
- Follows.following_id → Users.user_id
- TweetTags.tweet_id → Tweets.tweet_id
- TweetTags.tag_id → TAGS.tag_id

#### 3.3.4 性能优化索引
- Tweets.created_at (时间排序)
- Tweets.user_id (用户推文查询)
- Comments.created_at (评论时间排序)
- Comments.tweet_id (推文评论查询)
- Messages.created_at (消息时间排序)
- Messages.sender_id (发送消息查询)
- Messages.receiver_id (接收消息查询)

### 3.4 约束设计

#### 3.4.1 非空约束
- Users.username, email, password
- Tweets.user_id, content
- Comments.tweet_id, user_id, content
- Media.media_url, media_type
- TAGS.name
- Likes.user_id, tweet_id
- Messages.sender_id, receiver_id, content
- Reports.report_content

#### 3.4.2 默认值约束
- created_at: CURRENT_TIMESTAMP
- 所有时间字段自动设置

#### 3.4.3 检查约束
- Media.media_type IN ('image', 'video', 'all')
- 时间字段格式验证

### 3.5 表关系图

#### 3.5.1 主要关系
- Users → Tweets (1:N)
- Users → Comments (1:N)
- Users → Likes (1:N)
- Users → Messages (1:N)
- Users → Reports (1:N)
- Tweets → Comments (1:N)
- Tweets → Media (1:N)
- Tweets → Likes (1:N)
- Tweets → Reports (1:N)
- Tweets → TweetTags (1:N)
- TweetTags → TAGS (N:1)
- Comments → Comments (1:0..1)
- Comments → Reports (1:N)
- Users → Follows (M:N)

#### 3.5.2 自引用关系
- Tweets.parent_id → Tweets.tweet_id (推文转发)
- Comments.parent_id → Comments.comment_id (评论嵌套)

## 4. 数据完整性

### 4.1 实体完整性
- 所有表都有主键约束
- 主键字段不允许为空
- 主键值唯一

### 4.2 参照完整性
- 所有外键都有对应的主键引用
- 外键约束确保数据一致性
- 级联删除和更新策略

### 4.3 域完整性
- 数据类型约束
- 非空约束
- 唯一性约束
- 检查约束

## 5. 性能优化

### 5.1 索引策略
- 为常用查询字段创建索引
- 复合索引优化多字段查询
- 避免过度索引

### 5.2 查询优化
- 合理使用JOIN操作
- 避免SELECT *
- 使用LIMIT分页
- 优化WHERE条件

### 5.3 存储优化
- 选择合适的数据类型
- 合理使用TEXT和VARCHAR
- 避免冗余数据
